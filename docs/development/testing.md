# Testing

_For contributors writing or running tests._

Paths are relative to `src/app/` unless they start with `src/`, `tools/` or `docs/`.

There are two test suites: the TypeScript unit tests (Vitest in a real Chromium, [ADR 0009](../decisions/0009-unit-tests-in-real-chromium-with-vitest.md)) and the Python tests for the two pipelines (pytest). CI runs only the unit tests ([Deployment](deployment.md)); run the Python tests yourself when you change Python code.

## Unit tests

Specs sit next to the code as `*.spec.ts`. They run through the Angular builder `@angular/build:unit-test` with Vitest, in headless Chromium from Playwright, at a viewport of 1280×720 (`angular.json` → `test`).

```bash
npx playwright install chromium            # once per machine, and after a Playwright update
npm test                                   # watch mode
npm run test:ci                            # run once
npx ng test --include=<path>               # one spec file or folder
npx ng test --watch=false --coverage       # with coverage (HTML in coverage/, summary in the terminal)
```

Things to know:

- **All spec files share one browser context.** `src/test-setup.ts` calls `vi.restoreAllMocks()` after every test, so a `vi.spyOn` on `window`, `document` or `console` can't leak into the next file. `vi.fn()` mocks are not affected.
- **Layout is real.** Specs can measure elements. The wizard's step-layout specs use `mountInShellLayout` and `expectFillsStep` to check that each step's main box fills the available height ([Wizard](wizard.md#ui-helpers)).
- **Spy objects:** `src/testing/create-spy-obj.ts` builds typed spy objects, in the style of Jasmine's `createSpyObj`.
- **Wizard helpers:** `preprocessing-wizard/testing/preprocessing-test-helpers.ts` provides `createTestPreprocessingService()` and `createToastServiceSpy()`.
- **Workers:** the worker logic is tested through its pure parts (`workers/druid-runner.spec.ts`, `workers/pyodide-calls.spec.ts`, `workers/pyodide-files.spec.ts`), plus a smoke test that starts the real projection worker with DruidJS (`workers/projection.worker.spec.ts`); `preprocessing-wizard/services/preprocessing.service.worker-files.spec.ts` covers file pruning, `preprocessing.service.reload.spec.ts` next to it the restore of the uploaded file after a reload.

Vitest artifacts such as failure screenshots land in `.vitest-attachments/`.

## Python tests

```bash
python -B -m pytest -p no:cacheprovider tools/tests
```

| File | Covers |
|---|---|
| `tools/tests/test_preprocessing_config.py` | the wizard's pipeline (`src/assets/preprocessing_processor*.py`). Each test runs with default pandas and with pandas-3 behaviour enabled; the option values are read from the TypeScript enums, so a renamed option breaks the test. |
| `tools/tests/test_process_cli.py` | the CLI (`tools/process.py`, `tools/dataset_common.py`) |

`-B` and `-p no:cacheprovider` keep `__pycache__` and `.pytest_cache` out of the working tree.

## Manual testing

- **Sample data:** "Try with sample data" in Step 1 loads `src/assets/samples/wine-quality-red.csv` (regenerated by `tools/make-sample-csv.py`).
- **Bundled datasets:** `wineqr` and `nutrients` load on start.
- **Clean state:** the wizard state is in localStorage (`glyphspace_preprocessing_state`), processed datasets in IndexedDB (`glyphspace-datasets`). Clear both in the browser's developer tools to start fresh.
