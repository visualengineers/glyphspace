# Setup

_For contributors setting up GlyphSpace on their machine._

## Requirements

| Tool | Version | Used for |
|---|---|---|
| Node.js | 26 (`.nvmrc`; `package.json` accepts `>=26.0.0`, and `.npmrc` sets `engine-strict`, so npm refuses to install with an older Node) | the app, its tests and tooling |
| npm | the one that ships with Node (11.20 with Node 26.13) | dependencies (`package-lock.json`); older npm versions can drop entries that newer ones require, so update the lock file with a current npm |
| Python | 3.14 like Pyodide (3.11 or newer works), with the packages of `requirements-dev.txt`, plus `umap-learn` for adding bundled datasets | only for `tools/` (bundled datasets, Python tests) |

Create a virtual environment (`.venv/` and `venv/` are git-ignored) and install `requirements-dev.txt` into it: `python -m pip install -r requirements-dev.txt`. It pins the package versions that ship with Pyodide; `tools/process.py` additionally needs `pip install umap-learn`.

## First run

```bash
npm ci                            # install exactly what package-lock.json lists; also installs the git hooks
npx playwright install chromium   # once per machine: the browser the unit tests run in
npm start                         # dev server at http://localhost:4200/
```

`npm start` (and `npm run build`, `npm run watch`) first runs `tools/fetch-pyodide.mjs`. The first time, it downloads the Python packages of the wizard (about 27 MB) into `.pyodide-packages/`; afterwards it only checks their hashes and works offline. Calling `ng serve` or `ng build` directly skips this step, and the wizard then can't start its Python runtime.

Each Playwright version uses its own Chromium build. When an update of `package-lock.json` brings a new Playwright version, run `npx playwright install chromium` again.

The app loads the bundled datasets from `src/assets/data/` on start. The wizard's Python runtime (Pyodide with pandas and scikit-learn) is served by the dev server itself from `pyodide/` ([ADR 0013](../decisions/0013-self-host-pyodide.md)).

## Scripts

| Command | What it does |
|---|---|
| `npm start` | `tools/fetch-pyodide.mjs`, then `ng serve`, dev server with reload |
| `npm run build` | `tools/fetch-pyodide.mjs`, then the production build into `dist/glyphspace/` |
| `npm run watch` | `tools/fetch-pyodide.mjs`, then a development build, rebuilt on change |
| `npm test` | unit tests in watch mode ([Testing](testing.md)) |
| `npm run test:ci` | unit tests once |
| `npm run test:tools` | tests of the Node tools in `tools/` (`node --test`) |
| `npm run lint` | ESLint over `src/**/*.ts` and `src/**/*.html` |
| `npm run format` / `format:check` | Prettier over `src/**/*.{ts,html,scss,json}` |
| `python tools/process.py <file.csv>` | add a bundled dataset ([Preparing data](../user-guide/preparing-data.md)) |
| `python tools/process.py` | regenerate `src/default-dataset.ts` from the files in `src/assets/data/` |
| `python -B -m pytest -p no:cacheprovider tools/tests` | Python tests (after `pip install -r requirements-dev.txt`) |

Run the Python commands from the repository root. On Windows, `tools/process.py` imports `umap` before numpy, pandas and scikit-learn on purpose: otherwise llvmlite's DLL fails to load (WinError 1114).

## Line endings

`.gitattributes` keeps every text file LF, in the repository and in the working copy, whatever `core.autocrlf` is set to, so `npm run format:check` passes on Windows too. A working copy made before `.gitattributes` existed keeps its CRLF files until git rewrites them; on a clean working tree, `git rm -r -q --cached . && git reset -q --hard` rewrites them all at once.

## Git hooks

`npm ci` runs `husky` (the `prepare` script), which installs `.husky/pre-commit`. It runs `lint-staged` on the staged files: `eslint --fix` and `prettier --write` for `src/**/*.{ts,html}`, `prettier --write` for `src/**/*.{scss,json}`. Files outside `src/` (docs, Python) are not checked by the hook.

| `src/styles/` | SCSS tokens (`_variables.scss`) and mixins |
| `src/testing/`, `src/test-setup.ts` | shared test helpers and the per-test setup |
| `tools/` | the CLI for bundled datasets, the sample-data generator, the Python tests |
| `docs/` | this documentation ([index](../README.md)) |
| `CLAUDE.md` | guidance for Claude Code: where the docs are, the architecture in brief, the commands |
| `.github/workflows/deploy.yaml` | CI and deployment ([Deployment](deployment.md)) |
